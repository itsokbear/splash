# Плюх!

Браузерная головоломка: двадцать прудов, лягушка и волны, которые сдвигают кувшинки. TypeScript + Vite, HTML/CSS и SVG, без сервера и внешних ресурсов.

Играть онлайн: [itsokbear.github.io/splash](https://itsokbear.github.io/splash/).

## Запуск

Установка зависимостей, запуск, сборка и тестирование — **только в Docker**.

```sh
docker compose up -d --build game
```

Игра: [localhost:4173/play/plukh/](http://localhost:4173/play/plukh/). С телефона в той же сети: `http://IP-АДРЕС-MAC:4173/play/plukh/`. IP смотрите в настройках сети. Mac и Docker должны оставаться включёнными.

После изменений повторите команду. Код копируется в образы; постоянных bind mount нет. Контейнер автоматически запускается вместе с Docker Desktop. Остановка — `docker compose down`.

Dev-сервер: `docker compose --profile dev up --build dev`, адрес `http://localhost:5173`. После изменений требуется пересборка.

## Публикация

Репозиторий: [itsokbear/splash](https://github.com/itsokbear/splash). После отправки изменений в `main` процесс [публикации](.github/workflows/pages.yml) запускает все проверки через `./scripts/check.sh all` в Docker и передаёт проверенную production-сборку в GitHub Pages. При ошибке проверок сайт не обновляется. Сборки и результаты тестов не попадают в Git.

В настройках репозитория **Settings → Pages → Build and deployment → Source** должен быть выбран **GitHub Actions**. Ручной повтор доступен через **Actions → Проверка и публикация игры → Run workflow**. Секреты для публикации добавлять не нужно: используется встроенный `GITHUB_TOKEN`.

Относительный `base: './'` сохраняет работу ресурсов и Worker как по публичному адресу `/splash/`, так и локально в `/play/plukh/`. Прогресс хранится отдельно для каждого origin: локальное прохождение автоматически на публичный сайт не переносится.

## Проверки

```sh
./scripts/check.sh unit       # типы, модульные тесты, production-сборка
./scripts/check.sh reference  # независимая Python-модель
./scripts/check.sh e2e        # готовая игра + Chromium в Docker
./scripts/check.sh all        # все проверки
```

Скрипт пересобирает нужные образы, удаляет завершённые тестовые контейнеры и не сохраняет отчёты в рабочую папку. E2E поднимает игру выбранного Compose-проекта и оставляет её доступной после проверки.

Для сохранения снимков при отладке запустите `docker compose --profile checks run --name ИМЯ-КОНТЕЙНЕРА e2e`, скопируйте `/app/test-results` и `/app/playwright-report` через `docker cp` во временную папку вне проекта, затем удалите этот тестовый контейнер.

## Новые задачи

Создавайте новый диалог в проекте **Splash** с рабочей папкой в корне проекта. Постоянные инструкции — в [AGENTS.md](AGENTS.md); история предыдущих диалогов для начала работы не нужна. Укажите желаемое изменение и критерий готовности.

Диалоги в одной папке используют одни файлы: выполняйте изменения последовательно. Для параллельной разработки нужна отдельная копия проекта или worktree существующего Git-репозитория, своё имя Compose-проекта и свободные порты:

```sh
export COMPOSE_PROJECT_NAME=plukh-task-a
export PLUKH_PORT=4183
export PLUKH_DEV_PORT=5183
docker compose up -d --build game
./scripts/check.sh e2e
```

Эти переменные отделяют образы, контейнеры, сеть и порты. Используйте именно `COMPOSE_PROJECT_NAME`, а не только флаг `-p`: это также задаёт имена образов. Исходники переменные не изолируют. Основная ветка репозитория — `main`; её обновление запускает публикацию на GitHub Pages.

## Правила и данные

Первое нажатие выбирает цель, второе выполняет прыжок. Прыжки — прямо на 1–2 клетки. Приземление на лист отталкивает соседние листья; берег волну не создаёт. Отмена и число попыток не ограничены. `Tab` и `Enter`/`Space` управляют целями; `U` или `Ctrl/Cmd+Z` отменяет ход; `Escape` снимает выбор или открывает меню.

Сохранения: `plukh.progress.v1` в localStorage. Сохраняются результаты, выбранный уровень и звук; промежуточная попытка — нет. Игра опубликована на GitHub Pages; PWA не настроена. Эмуляция телефона в Chromium не заменяет проверки на настоящих устройствах и Safari.

Уровни 1–5 сохраняют исходные раскладки. Уровни 6–20 рассчитаны на 9–30 ходов по кратчайшему решению: 9, 10, 11, 12, 13, 14, 15, 16, 18, 20, 22, 24, 26, 28, 30. В 11 новых уровнях камни удерживают листья или перекрывают короткий путь; удаление каждого камня меняет кратчайшее решение либо делает уровень непроходимым. Лимита ходов в самой игре нет. Старый прогресс сохраняется: прохождение уровня 5 открывает уровень 6.

Новый уровень добавляется в `levels.json`, затем проверяется валидатором, эталонным маршрутом и BFS в обеих моделях правил. Список и финальный экран используют фактическое число уровней. При расширении обновите ожидания тестов кампании и проверьте подсказки в Worker, переходы и прокрутку списка. Версию образа Playwright в Dockerfile обновляйте вместе с `@playwright/test` в lock-файле.
