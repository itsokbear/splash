# Плюх! — инструкции для задач проекта

## Начало работы

- Работай из корня проекта. Прочитай README и относящиеся к задаче исходники; не полагайся на историю других диалогов.
- Источник правил — `plukh_codex/plukh_codex_spec.md`, раскладок — `plukh_codex/levels.json`. Изображение в `references/` задаёт стиль, а не координаты поля.
- Сохраняй текущий стек: TypeScript + Vite, HTML/CSS, SVG. Интерфейс и общение с пользователем — на русском.

## Среда

- Установка зависимостей, запуск, сборка, тесты и браузерная автоматизация — только в Docker. Не устанавливай Node/Python/браузеры на хост для этого проекта.
- Команды — в README; проверяй через `./scripts/check.sh`. Скрипт работает без локального `node_modules`.
- Исходники копируются в образы. После изменений пересобирай нужные сервисы; не тестируй старую сборку.
- Не добавляй постоянные bind mount: здесь уже зависал файловый обмен Docker Desktop gRPC FUSE. Зависимости и результаты тестов оставляй в контейнерах.
- Основной адрес — `http://localhost:4173/play/plukh/`; порт игры доступен в локальной сети. Сохраняй относительный `base` и работу Worker из подпапки.
- Не перезапускай Docker Desktop, не очищай общие образы/volumes и не останавливай чужие приложения как часть обычной задачи.

## Границы модулей и инварианты

- `src/core/` не зависит от DOM, времени, аудио и localStorage. `simulateMove` — единая реализация для хода, предпросмотра и решателя; входное состояние не изменяется.
- Волну рассчитывай по одному снимку, применяй сдвиги одновременно. Без цепных толчков и пропажи листьев. Посадка на сушу не создаёт волну.
- История хранит весь предыдущий ход; предпросмотр её не меняет. Анимация показывает уже принятый переход и блокирует повторный ввод.
- Подсказка ищет маршрут из текущего состояния в Worker. Сохраняй защиту от старых ответов и callback после смены сессии.
- Сохраняй существующие результаты и ключ `plukh.progress.v1`; изменения формата требуют миграции. Отказ хранилища или звука не должен ломать игру.
- Правила и BFS — `core/`; состояние и сохранения — `app/`; графика — `ui/`; интерфейс — `main.ts` и `style.css`.

## Проверка и завершение

- Для TypeScript и логики: `./scripts/check.sh unit`. Для правил/данных также `reference`; для UI, ввода, Worker, сохранений, Docker и публикации — E2E через `./scripts/check.sh e2e`.
- Для документации достаточно проверить команды, ссылки и конфигурацию; не запускай весь набор без причины.
- Проверяй телефонные размеры 390×844 и 360×640, desktop 1280×800, клавиатуру и reduced motion, когда они затронуты.
- Поддерживай исходники, тесты и актуальную документацию. Не создавай отчёт о каждом диалоге, журнал действий или файл «текущего статуса».
- Снимки, traces, сборки, кэши и результаты тестов не оставляй в проекте. При необходимости сохраняй их во временную папку вне проекта и дай ссылку в ответе.
- В итоге кратко опиши изменения, выполненные проверки и ограничения. Обнови README/эти инструкции только при изменении постоянных правил работы.

## Несколько задач

- Отдельный диалог не изолирует файлы. Не перезаписывай изменения других задач; перед редактированием прочитай текущее содержимое и проверь Git diff, если Git настроен.
- Для одновременной работы используй отдельную копию или существующий worktree, уникальные `COMPOSE_PROJECT_NAME`, `PLUKH_PORT`, `PLUKH_DEV_PORT` (пример в README). Это разделяет Docker-ресурсы.
- Имя задавай переменной `COMPOSE_PROJECT_NAME`: в установленной версии Compose одного `-p` недостаточно для подстановки имени образов.
- Работая в изолированной задаче, не пересобирай и не останавливай основной проект `plukh`. Удаляй только собственные временные контейнеры.
